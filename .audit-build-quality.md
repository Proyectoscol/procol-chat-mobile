## Resultados pnpm audit

**88 vulnerabilidades** en total. Las mas relevantes para este proyecto:

| Severidad | Paquete | Descripcion | Via |
|-----------|---------|-------------|-----|
| CRITICA | `protobufjs` | Ejecucion de codigo arbitrario | `@react-native-firebase/app > firebase > @firebase/firestore > @grpc/proto-loader` |
| CRITICA | `shell-quote` | Inyeccion de shell via newlines | `react-native > react-devtools-core` (solo en dev) |
| ALTA | `flatted` (x2) | DoS y prototype pollution en parse() | `eslint > file-entry-cache` (solo en dev) |
| ALTA | `undici` (x3) | Vulnerabilidades WebSocket | `expo > @expo/cli` (solo en dev/build) |
| ALTA | `node-forge` (x4) | Bypass de certificados, signature forgery | `pnpm overrides` ya aplica `^1.3.2` - verificar si corrige |
| ALTA | `picomatch` (x3) | ReDoS via extglob | `expo > @expo/cli` (solo en dev) |
| ALTA | `lodash` | Code injection via `_.template` | Dependencia directa (runtime) |

**Analisis:**
- `shell-quote`, `flatted`, `undici`, `picomatch` solo afectan el entorno de desarrollo/build, no el bundle de produccion.
- `protobufjs` esta en la cadena de Firebase - actualizar Firebase a la version que incluya `protobufjs >= 7.5.5` resolveria esto, pero requiere prueba de regresion completa de FCM.
- `lodash` es runtime. La vulnerabilidad en `_.template` no es explotable si el template input no viene de usuario no confiable (verificar usos en el proyecto).
- `node-forge` ya tiene override `^1.3.2` en pnpm.overrides - el fix puede ya estar aplicado transitivamente.

**Accion:** No corregidas automaticamente. Actualizar Firebase o lodash puede romper compatibilidad con Expo SDK. Requiere decision informada y prueba en dispositivo.

## Alineacion build config

`eas.json` y los scripts de `package.json` estan alineados:
- `build:android` -> `eas build -p android --profile production` (cloud, produce AAB para Play Store)
- `build:android:local` -> `eas build -p android --profile production --local` (local, produce AAB)
- Para APK de sideloading: `cd android && ./gradlew assembleRelease` (documentado ahora en README.md)

El perfil `production` en `eas.json` tiene `autoIncrement: true` - en builds locales esto puede generar conflictos si el versionCode esta fuera de sincronizacion con el servidor EAS. Considerar usar `--no-auto-increment` para builds locales de prueba.
